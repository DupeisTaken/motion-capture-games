The diagnostic console now releases only an acknowledged source epoch, waits for cancelled startup to settle, and keeps failed release visible and retryable.

Issue #26 · Implementation PR

Problem and correction

A named camera can disappear before startup. The service correctly rejects that choice before replacing its existing source, but the console previously followed the rejection with an epoch-less stop. That stopped another tab's source. Stop also discarded late startup acknowledgments, while pagehide allowed pending startup to create new sockets. Failed release unlocked replacement controls and exposed no retry.

Startup, active display and acknowledged release now have separate state. A cancelled start remains pending until its result is known. Accepted epochs are retained before error or obsolete-generation handling. The shared CameraReleases helper scopes and deduplicates cleanup, preserves failed epochs and retries serially. Neither a failed start nor global status authorizes stopping an unknown owner.

One generation owns its preview/observation sockets and animation. Stop, hidden visibility, pagehide and either stream's failure invalidate that generation, close the pair, clear current imagery and reject late decoded bitmaps. Release is registered before display reset, so a renderer failure cannot lose cleanup. Delayed setup/fullscreen/status callbacks cannot hide ownership warnings or unlock controls.

Protocol and hardware limits

If startup succeeds but its response is lost, the current protocol cannot safely identify that tab's epoch. The console reports unknown ownership and blocks replacement. Recovery requires restarting the shared local vision service and then reloading the page; this affects other tabs. A request token or lease is separate future protocol work.

Page destruction before acknowledgment and browser keepalive delivery remain best-effort limits. Local preview shutdown and socket closure do not prove physical driver release. This change makes no USB camera, Windows/macOS/Linux driver, browser unload, inference, physical latency or multiplayer certification claim. The optional unscoped service stop API remains compatible, but the console never uses it.
