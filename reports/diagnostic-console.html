What changed and why

A denser operator workspace

  • Controls, preview and diagnostics share three desktop columns. Detections sit below the preview; stream metadata sits below timings. Mobile stacks the same information.
  • The preview has a 16:9 desktop stage. Compact headings, fields and person cards replace large empty margins.
  • Added source processing/p95, validation + JPEG decode, canvas draw submission, source work, arrival age, packet size and sample count alongside existing rate, inference, geometry and drop count.

Performance fixes grounded in evidence

  • Unchanged person cards retain their DOM nodes. Timing values use cached elements/text writes instead of repeated HTML parsing. Diagnostics refresh at most four times per second.
  • A bounded 120-sample rolling window calculates received-update rate and nearest-rank processing p95.
  • Capture, freshness and stage durations now share the high-resolution monotonic host clock. Synthetic pacing follows fixed deadlines and skips missed ticks.

Camera permission and physical-device selection

Allow & discover cameras explicitly requests video access without a microphone. It reveals camera names, then releases every discovery track. Select a browser camera and choose Identify for a temporary local preview. Releasing, switching sources, hiding/closing the page or starting native capture stops the browser tracks. Late permission results are released too.

Browser IDs and enumeration order cannot reliably select an OpenCV index. The console labels the browser camera as a reference and retains an explicit native index (0–9), which the operator verifies against the live diagnostic view. Browser permission and Python/OS permission are separate. Automatic native mapping, stable installation identities and simultaneous multi-camera input remain open.

Camera names, IDs and identification video are not persisted. This report contains generated bodies, never participant footage. Camera permission/device behavior was tested with mocks; no physical camera was opened during verification.

Remaining limits and next work

  • The preview still follows inference cadence. A fast display refresh or CPU model smoke test would not demonstrate a smooth independent camera feed. Issue #10 owns that media/rendering work.
  • Camera formats, USB contention, GPU/CPU model throughput with people, physical latency, one-/three-person crossings, macOS and production packaging remain unverified.
  • Native-index mapping requires operator verification. Browser discovery cannot establish native OS device identity; another tab or application can still contend for a device.
  • Telemetry diagnoses stages but excludes compositor, display scanout and verified exposure timing. Existing freshness limits and ambiguity behavior remain in force.
