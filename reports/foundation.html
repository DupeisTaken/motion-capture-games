Documentation foundation

A shared platform for games played through movement.

The repository now records the product, architecture, ownership rules and evidence needed to build a digital mirror for one player, then three players moving freely.

No gameplay, camera pipeline or pose model is implemented. Technology candidates and performance targets remain explicitly unvalidated.

One shared motion path, separate game rules

The foundation gives each component a clear owner. Games receive model-independent input; the session owns player slots; vision publishes observations and uncertainty.

  1. Two camerasPrimary mirror view and a useful alternate angle.
  2. VisionAcquire, infer, track and preserve source timing.
  3. MotionMap coordinates and produce valid motion segments.
  4. Session & gameOwn player slots, interactions and scoring.
  5. MirrorCompose live video, graphics and sound.

Architecture schematic, not a screenshot of an existing application. Video also travels directly from vision to the compositor; its timing must remain correlated with observations.

Conventions added

  • Explicit anatomical joints, coordinate spaces, transforms and clock domains.
  • Bounded queues, stale/uncertain-input handling and motion-trail resets.
  • Canonical pose replay and game-input replay as distinct verification boundaries.
  • Local environments, pinned dependencies when implementation starts, and shared protocol generation.
  • Meaningful tests, real-server UI evidence, scoped PRs and standalone reports.
  • Ignore rules for local credentials, recordings, weights, dependencies and build output.

Build in evidence-driven slices

  1. Diagnostic mirror

    Test actual camera modes, video delivery, alignment, one-player motion and three-player crossings. Select the model and certify the initial profile.

  2. Whack-a-mole

    Complete joining, practice, reach interaction, scoring, results and recovery for one player, then three.

  3. Fruit slicing

    Validate fast swept motion, trail breaks, repeat-hit prevention and attribution.

  4. Dodgeball

    Validate body regions, obstacle timing and fair uncertainty handling. Add depth only with a demonstrated need.

  5. Deployment profiles

    Package for offline use and certify additional Windows/macOS tiers with explicit capacity.

Remaining limitations

  • No runtime code, protocol schemas, model weights, dependency manifests, automated CI or deployment package exists yet.
  • Camera formats, synchronization, room layout, final host hardware and all performance claims need validation.
  • Complete occlusion may prevent reliable identity recovery; explicit rejoining is an accepted fallback.
  • No Git remote was configured. No GitHub issue or PR was created; local milestone briefs and templates are ready for a chosen destination.
  • The docs and report are English only. No additional language is claimed or tested.
