One home for every game.

The root URL now opens a game directory with Slap a Mole, Dodgeball, Motion Runner and Virtual Maze. The tracking console and two-camera workspace sit below the games as operator tools. The console moves to /diagnostics.html; existing game URLs remain valid.

Issue #54 · Ready-for-review pull request

What changed and why

  • Four named, illustrated game cards make all implemented games discoverable. Each states its input options; Virtual Maze explicitly says synthetic rehearsal and physical input pending.
  • Static HTML links work without JavaScript. Local CSS and decorative inline SVG require no remote assets. Directory loading imports no game or camera runtime and sends no vision-service requests.
  • Game headers provide All games and corrected Tracking console links. Brand links return home. Rig console links, diagnostic lifecycle/vision verification and the preview benchmark use the explicit diagnostic route.
  • README, app ownership, architecture, roadmap, diagnostic guide, test guide and CI build coverage document seven entries. A directory test compares game cards with actual playable HTML files so a future game cannot silently disappear from the list.

Limits and compatibility

Bookmarks to / or /index.html now show the directory; use /diagnostics.html for the console. Existing game routes, scoring, identity and capture ownership remain unchanged. Adding games requires an explicit card, build entry and accurate input description. Browser transport mocks do not verify physical camera capture, movement recognition, live XYZ or latency; those milestone gates remain open.

Windows; Node 24.16.0 (local installed version; repository pin 24.21.0), pnpm 11.25.0, Python 3.12.16. Dependencies installed from frozen pnpm and locked uv manifests. Hosted CI uses pinned versions.
