The measured workflow

  1. Choose the physical rectangle. Independently measure width/depth, each 5–10 m. Fix mounts; record and lock crop, rotation, focus, optical/digital zoom.
  2. Explicitly Start camera 1. Discovery is metadata-only. Freeze a current raw, unmirrored preview and mark near-left, near-right, far-right, far-left. These are floor contacts in stable physical correspondence.
  3. Move and rotate an independent reference. Measure a rigid edge from 0.2–2 m. Near-left: along width; centre: diagonal; far-right: along depth. Resume, wait for a newly displayed image, freeze and mark both endpoints for each placement. A double click cannot reuse the old image.
  4. Fit and check independently. Only floor corners fit the homography. Reference lengths, spread and directions are checked afterward. A single small object at one position cannot establish arbitrary geometry. A tiny four-corner residual is expected and is not accuracy evidence.
  5. Stop, then use camera 2. Await acknowledged release before switching roles/devices. Repeat the same named physical corners and reference procedure. Two floor mappings remain a floor-only foundation, not stereo extrinsics or body reconstruction.

Ownership and recovery

The additive /api/calibration/start endpoint shares the service's acquisition owner and a start gate, refuses an active source, and never opens a second camera for preview. Preview requests are bounded to one in flight, with epoch/sequence/source/geometry validation. /api/calibration/floor is a camera-free bounded 32 KiB geometry endpoint. Games and the canonical physical-input gate are unchanged.

Only acknowledged epochs are stopped. Pending cancellation cleans up a late acknowledgement; failed release keeps replacement blocked with retry. Every unusable successful Start response—including JSON null, primitives and malformed JSON—retains unknown ownership and requires service restart/reload rather than guessing an epoch.

The internal calibration controller exposes a read-only blocker; mountMaze.navigationBlocker() implements the shared navigation-owner method and combines capture ownership with the participant window. Local same-tab route links are blocked while capture is active, pending, unreleased or unknown. The navigation campaign PR must compose this method, not overwrite it. Browser/tab closure still cannot guarantee asynchronous release; explicitly Stop before leaving.
